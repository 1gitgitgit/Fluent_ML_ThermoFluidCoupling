## 冷却优化代码做了什么

---

**为什么要写这段代码**
CFD仿真每跑一次要很久，但优化器需要反复尝试成千上万种参数组合。所以思路是：先用35次真实CFD结果训练一个"山寨CFD"（代理模型），后面让优化器只调用这个山寨版，速度从小时级变成秒级。

---

**第一步：读数据**
读取35个CFD工况，每行是一个仿真结果。输入是进口速度v和进口温度T，输出是最大速度vmax和最高温度tmax。

---

**第二步：训练代理模型**
用这35个点分别训练四个机器学习模型——RandomForest和LightGBM各训练一个预测vmax的、一个预测tmax的，共四个。35个点太少不能单独留测试集，所以用5折交叉验证：把数据切成5份轮流验证，得到R²评分，谁高选谁，自动决定最终用RF还是LGB。

---

**第三步：画响应面（验证代理模型是否靠谱）**
自己人为造了60×60=3600个均匀网格点（原来35个点是真实CFD，这3600个是自己编的），全部喂给代理模型预测，把预测结果画成带颜色的等高线图。再把原始35个真实样本点叠加上去对比，看代理模型在已知点附近预测对不对，对了才说明插值合理可以继续用。

---

**第四步：定义优化问题**
写一个类继承pymoo库的Problem父类，父类是空模板，子类填入具体内容：2个设计变量（v和T）、2个优化目标（vmax和tmax都越小越好）、变量的上下限范围。`_evaluate`方法是优化器每次评估时自动调用的，传进来一批参数，调用代理模型预测，结果写入固定键名`out["F"]`。最后实例化这个类得到`problem`对象，相当于从空白模板做出了一张填好的表。

---

**第五步：NSGA-II跑优化**
启动遗传算法。第0代随机撒100个设计方案（100个个体），每个个体是一个`[v, T]`组合。之后每代：90%概率发生交叉重组（两个父代混合生成子代）、小概率变异（对参数做小扰动防止陷入局部最优），跑满200代停止。总共评估100×200=20000次，全走代理模型所以秒级完成。最终输出Pareto前沿——一组互不支配的最优解，每个解都是"在不牺牲某一个目标的前提下无法再改进另一个目标"的方案。

---

**第六步：从Pareto前沿选推荐点**
Pareto前沿有很多解，提取三个有工程意义的点。最低tmax（散热最极致）、最低vmax（最省泵功）、折中方案。折中方案的做法：先把vmax和tmax都min-max归一化到0\~1（因为两者量纲差距很大，不归一化tmax会完全压制vmax），归一化后算每个解到原点的欧氏距离，距离最小的就是两个目标最平衡的折中解。

---

**第七步：逆问题（反推参数）**
三个工具函数。第一个：给定tmax上限（如320K），用differential_evolution单目标优化，在满足tmax≤320K这个约束的前提下反推v_inlet最小能取多少，相当于在约束下省功耗。第二个：在设计空间撒10000个点预测tmax，画出哪片区域满足约束、哪片不满足，让工程师直观看可行域有多大。第三个：工程师说"我希望vmax≈0.05、tmax≈320K"，但这个期望点不一定在Pareto前沿上，就从已有Pareto解里找归一化欧氏距离最近的那个真实可行解推荐给他。

```
# ============================================================
# 整体流程总览
# ============================================================
#
# 这个脚本做了三件事：
#
# 【第一件事】训练代理模型（第2-3块）
#   CFD仿真很慢，跑一次要很久。
#   所以先用已有的35个CFD样本，训练两个机器学习模型：
#     - 一个预测 vmax（流速）
#     - 一个预测 tmax（温度）
#   训练完之后，预测一个新点只需要毫秒，相当于造了个"廉价替身"。
#
# 【第二件事】用代理模型找最优方案（第4-9块）
#   第4块：响应面可视化
#     在v和T的范围内均匀撒3600个点，全喂给代理模型预测，
#     画成等高线图。这是"看地图"——看全局长什么样，验证模型合不合理。
#     但光看地图找不到最优，因为：
#       - 最优点不一定恰好落在网格上
#       - 两个目标同时最优的权衡边界（Pareto前沿）靠肉眼根本看不出来
#
#   第5-9块：Problem + NSGA-II 优化模块
#     这俩是一个模块，Problem负责"定义怎么算分"，NSGA-II负责"怎么找高分"。
#     设计空间还是那个v和T的空间，NSGA-II只是更聪明地在里面找点。
#     它像导航一样，朝更优的方向进化，100个个体×200代，
#     最终找到一条Pareto前沿——上面每个点都是某种权衡下的最优解。
#
#     为什么不直接用3600个网格点找最优？
#     因为那是"均匀撒点看全貌"，不是"有方向地找最优"，
#     Pareto前沿靠撒网格是找不到的。
#
#     为什么不直接调代理模型预测，而是要引入Problem这个壳子？
#     因为NSGA-II不认识你的代理模型，只认识pymoo规定的Problem格式。
#     Problem就是个转接头，代理模型插一头，NSGA-II插另一头，中间对接。
#
# 【第三件事】逆问题：从需求反推方案（第10-12块）
#   NSGA-II给你的是"一堆权衡方案"（Pareto前沿），
#   但工程师通常有具体要求，比如：
#     - "tmax不能超过320K，在这个前提下v越小越好"
#     - "我想要vmax≈0.05、tmax≈320，最接近这个的是哪个方案"
#   Pareto前沿回答的是"有哪些好方案"，
#   逆问题回答的是"我的条件对应哪个方案"。
#
# ============================================================
```
